# SecureShield

## Overview
SecureShield is a machine learning-driven endpoint threat detection and forensic correlation system. It evaluates the robustness and separability of network/endpoint telemetry features using the CIC-MalMem-2022 dataset, and demonstrates how integrating forensic structural relationships (temporal, process, file, network) significantly reduces actionable false positives.

## Problem Statement
While machine learning models often achieve near-perfect offline accuracy (e.g., AUC 1.000) on curated benchmark datasets like CIC-MalMem-2022, this offline performance frequently relies on dataset-specific feature separability rather than true real-world generalization. Simple numerical feature perturbations can drastically degrade ML-only confidence. SecureShield addresses this gap by augmenting ML predictions with a deterministic, multi-dimensional forensic correlation engine.

## Architecture
The system consists of:
1. **Core ML Pipeline (`src/secureshield/` & `experiments/`)**: Performs dataset processing, model training, SHAP feature importance analysis, noise perturbation, and incident correlation.
2. **FastAPI Backend (`backend/`)**: Serves the generated experimental artifacts, mock inference, and simulated forensic scenarios to the frontend.
3. **React Frontend (`frontend/`)**: Provides an interactive dashboard for visualizing model performance, SHAP values, MITRE ATT&CK mappings, and the synthesized forensic graphs.

## Pipeline & Dataset
*   **Dataset**: Uses the CIC-MalMem-2022 dataset.
*   **Features**: Selects 14 core features (e.g., `svcscan.nservices`, `pslist.nppid`) based on high non-linear separability.
*   **Experimentation**: 
    *   **Robustness**: Injects synthetic noise to stress-test numerical thresholds.
    *   **Correlation Ablation**: Measures confidence changes when restricting dimensions to temporal-only vs. full context.
    *   **Comparative Stats**: Evaluates a controlled subset (10 ML FPs, 10 ML TPs) and demonstrates 0/10 actionable FPs and 10/10 actionable TPs after SecureShield's forensic correlation is applied.

## Methodology
The experiments use a strict 80/20 train/test split. No manually altered values exist in the pipeline; all reported numbers are directly generated by the experiments. Note that the correlation comparison utilizes a *controlled simulated forensic scenario*, as the underlying dataset lacks native timestamped structural logs.

## Reproducibility Instructions
To regenerate the full suite of research artifacts:

```bash
# 1. Ensure dependencies are installed (e.g., pandas, scikit-learn, shap, networkx)
# 2. Add the source directory to your PYTHONPATH and run the pipeline
export PYTHONPATH=src
python3 run_experiments.py
```
This will recreate the `.csv` tables in `experiments/results/tables/`.

## Running the Application
### Backend Startup
```bash
cd backend
export PYTHONPATH=../src
uvicorn main:app --reload --port 8000
```
### Frontend Startup
```bash
cd frontend
npm install
npm run dev -- --port 3000
```

## Research Limitations
*   **Dataset Limitations**: CIC-MalMem-2022 has no native endpoint timestamps or network events. Forensic timeline events are analytically derived and simulated for testing correlation logic.
*   **Generalization**: The 1.000 AUC reflects specific sandbox separability, not real-world deployment performance.
*   **Stress Testing**: Feature perturbation evaluates threshold sensitivity, it is not a proof of real-world adversarial robustness.

## Provenance Policy
SecureShield displays data with strict provenance markers:
*   `MEASURED`: Extracted directly from the original dataset features.
*   `DERIVED`: Calculated via mathematical transformation of measured features.
*   `SIMULATED`: Synthetically generated for the controlled forensic correlation scenario.

## Security Note
This dashboard is hardened for local and conference demonstration environments. The API is locked to local origins, paths are validated, and errors are sanitized. It is **not intended** for exposure on the open internet without adding robust authentication and authorization layers. Please review `SECURITY_AUDIT.md` for full details.

## Conference/Demo Instructions
To present the demo, simply run both the frontend and backend servers locally as described above. The dashboard explicitly relies on the pre-generated research `.csv` outputs. Ensure that `run_experiments.py` has been successfully executed prior to the demonstration.
